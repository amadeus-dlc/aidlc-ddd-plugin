# 本家参照用サブモジュールの保護

`aidlc-workflows/` は参照専用です。この作業コピーでは、作業ツリーと対応するGit管理領域を読み取り専用に設定しました。
参照リビジョンは `a277af218f0df7f325d3b8be7b6d90fce2c5bd40` のままで、作業ツリーに差分はありません。
誤って加えたソースと生成物の変更は取り消し、私が導入したサブモジュール内の `node_modules/` も削除しました。

## 設定

- 作業ツリーとGit管理領域のファイル・ディレクトリから書き込み権限を除去。
- macOSのACLで、両ルートディレクトリ自身の削除・名前変更を拒否。
- サブモジュールのローカル `core.hooksPath` に、常に拒否する `pre-commit`・`pre-push` を設定。
- `push.default = nothing` とし、`origin` のpush先を送信できないローカルパス `/dev/null/aidlc-workflows-read-only` に設定。fetch先は維持。
- 親の `AGENTS.md` に、参照元への書き込みと保護設定の自律解除を禁止するルールを記載。

親リポジトリ自体のcommit・push設定は変更していません。
互換性修正とビルドは `.claude/`・`.codex/`・`ddd/` 側で行います。

## 検証

作業ツリーとGit管理領域でのファイル作成が拒否されること、両フックが終了コード1を返すこと、
`git push --dry-run origin HEAD` が送信不可のローカルパスで失敗することを確認しました。
実際のcommitやリモートへのpushは行っていません。
検証の生ログは `ddd-sandbox/reference-protection/verification.json` にあります。

## 制約

これは誤操作防止の設定です。同じOSユーザーが意図的に権限を戻したり、フックや送信先設定を回避したりする操作まで防ぐ独立したセキュリティ境界ではありません。
ファイル権限・ACL・ローカルGit設定は新しいcloneには引き継がれません。別の作業コピーでも参照専用として保護する必要があります。
参照元の更新・保護解除は、ユーザーからの明示的な更新指示があった場合だけ扱います。
