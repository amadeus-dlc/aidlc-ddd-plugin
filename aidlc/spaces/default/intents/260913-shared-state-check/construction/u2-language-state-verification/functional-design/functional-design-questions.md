## Already Confirmed

U2はRustStateEvidence、TypeScriptStateEvidence、StateExposureVerificationを所有する。共通契約と最終判定はU1が所有し、U2で再定義しない。指定した固定入力を使い、一般のパッケージ探索・名前解決・移行・本番切替を追加しない。

Rustは名前付き・タプル構造体の非公開・公開・制限付き公開を扱う。TypeScriptはclassの非公開フィールドと、型＋同名コンパニオン・クロージャ・非公開ブランドの表現を扱う。操作メソッド固有の振る舞いや汎用的な可変参照の安全性を証明する範囲ではない。

以下はその対応範囲を固定ケースと手順へ具体化する内容である。独立した業務判断の未回答事項はない。

## Consolidated Summary Confirmation

- 四成果物を作る。entities.mdには検証ケース・実行記録と内部で使う値、rules.mdには対象同定・抽出・実行管理・比較の規則、functional-spec.mdには抽出と検証の手順・状態分岐・対応形状、traceability.jsonにはU2の16受入条件と規則の対応を記録する。
- 一回の検証で使うソース内容・有効設定・ツール版を確定してU1へ要求を準備させ、その同じ値で抽出する。途中でソースを読み直さず、別入力の応答・別対象の結果を混在させない。
- Rustは指定ファイル内の宣言経路から構造体を一意に同定し、名前付き・タプルのフィールドを扱う。非公開は非公開、pubと制限付き公開は公開の根拠へ変換する。条件付き構文や未展開マクロ等で型・フィールドの成立を確認できない範囲は未解決とし、構文候補を確定違反へ変換しない。
- TypeScriptは準備済みの入力と設定から構文・シンボル・型を確認する。classの非公開フィールドと公開データメンバー、操作メソッドを区別する。readonlyを公開から除外せず、型検査だけのprivate修飾子を実行時の非公開フィールドと同一視しない。
- コンパニオン形式では、同じファイルの型と同名コンパニオン、非公開のunique symbolブランド、局所的に定義されたインスタンスのオブジェクト、閉じ込めた状態を確認する。合意済み例の局所instanceを成功値へ包んで返す形を扱い、内側の操作メソッドのreturnを生成関数のreturnと取り違えない。エラー集合の照合や外部Resultライブラリの統合は追加しない。
- 継承、spread、未対応の計算名、型アサーション、外部の値・型の解決、追えないインスタンス生成経路など、対応形状で必要情報を確認できない場合は範囲と理由を未解決にする。非公開ブランドの確認済みの計算名は、未対応の計算名と区別する。
- 両言語の根拠をC1のFact・一覧の完全性・対象証跡へ変換し、同じ本文から共通の行・UTF-8バイト位置を作る。構文木や解析器固有の型はU2内に閉じる。公開の有無と完全性からの最終判定はU1へ委ねる。
- 実行は準備・起動・完了・失敗・期限切れ・出力超過を区別する。C2の保護値と再試行なしを維持し、実際に終了できる実行境界で管理する。不完全な出力を証跡として採用せず、responseなしはnull、起動不能と実行失敗は対応する実行状態へ変換する。
- 固定ケースごとに期待結果を保持し、実際の結果から期待値を作らない。正常時のtarget・checkedEvidenceも含む比較で、根拠だけの差や期待と異なる理由の検査不能を検出する。意図した異常の検出と、実際の準備不足や未実行を区別する。
- 検証コマンドの終了コード0〜3、JSON報告と診断の分離、必要ツール・対応範囲・採用版・明示的な準備手順の英日案内をC2どおりに具体化する。既存Rust回帰と新経路を自動検証へ接続し、未実行の経路を成功扱いしない。
- 実装コードや新しい本番基盤は作らず、各言語の対応形状、失敗境界、ケース、依存と試験担当を機能設計として定める。U1との契約変更が必要と分かった場合は、その影響を明示して契約へ戻し、U2だけで意味を変えない。
