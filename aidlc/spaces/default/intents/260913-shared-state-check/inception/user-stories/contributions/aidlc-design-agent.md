## Contribution

二つのペルソナと四つのストーリーは、指定型を検査する開発者と、その結果を判断するレビュー担当者の目的に沿っている。FR6.2の再実行案内を受入条件へ明記する修正を求める。結果の読み分けと試験境界については、意味を変えずに補足できる文案を示す。

確認範囲は、指定されたステージ定義、personas.md、stories.md、質問・確認済み方針、requirements.md、business-overview.md、component-inventory.mdである。コード実行による検証は行っていない。以下は草案の評価と統合案であり、実装済みの成果を示すものではない。

### D1: 再実行案内に期待結果・終了状態・実使用ツール版を残す

[AC1.4.6](../stories.md#ac146-検証条件と範囲を残す)は必要ツールと採用API版を列挙しているが、[FR6.2](../../requirements-analysis/requirements.md#fr6-再実行可能な検証経路を提供する)が求める「期待する結果と終了状態」と、実際に使ったツールのバージョンが明記されていない。文書だけで再実行するP1には、違反・検査不能を意図したケースで試験が成功したのか、試験そのものが失敗したのかを判断する手掛かりが必要である。AC1.4.3で区別した意味を、利用方法にも引き継ぐ。

AC1.4.6のThenを次の文案へ置き換えることを提案する。

> 必要ツールと採用API版、対応形状と未対応形状、実行コマンドを英日文書へ記載する。各ケースの期待する規則結果と、検証コマンドの期待する終了状態も示す。実行記録には、実際に使用したツールの版、環境、コマンド、実行したケースと成否を残す。未実行の環境を検証済みと記載しない。

具体的な終了コードや記録形式は後続設計に委ねられる。追加の配布・運用要件は生じない。

### D2: 検査不能でも確定違反を読める条件は妥当

AC1.3.2〜AC1.3.5は、空の所見、確定違反と未解決の混在、未検証応答、実行失敗を区別している。P2の「修正箇所と追加確認箇所を判断する」という目的に対応し、FR5の優先順位を保っている。

AC1.3.3の「両方を残す」を利用者の読み取りまで明確にする場合は、次の一文をThenへ補足できる。

> 結果を確認する人が、全体の検査不能、確定違反の対象・位置・根拠、未解決の対象・範囲・理由を、それぞれ区別して読み取れる。

これは既存の結果出力が伝える内容の明確化である。新しい画面や対話操作、認証ロールを追加せず、具体的なJSONキーや文章の書式も固定しない。

### D3: US1.4は利用価値を持ち、試験境界の具体化で四本構成を維持できる

US1.4の価値は、P1が文書の条件で検証を再実行し、変更による差を見つけられることにある。Rust二形式・TypeScript二形式と一規則に限定しているため、汎用テスト基盤のストーリーへ広げる必要はない。US1.1〜US1.3への最終結合の依存も明示されている。

一方、「入力・期待値・記録の境界を独立に試験できる」だけでは、その独立性を確認する例が読み取りにくい。Scope and INVESTに、次の文案を加えるとよい。

> 固定した検査結果と期待値を用い、一致・不一致を判別する処理と、実行条件・成否を記録する処理を独立に試験する。必要ツールがない条件では、検証成功にせず理由を返すことを確認する。これらの試験とは別に、AC1.4.1では実際の両言語の抽出から共通判定までを実行する。

共通判定の単独試験はU1、言語別抽出と検証実行はU2という確認済みの責務に沿う。AC1.4.5のNFR3も維持し、独立した試験を最終結合の代替にしない。

### ペルソナに追加変更は不要

P1は検査の利用と保守、P2は結果の判断を担当し、同じ人が両方を担うことも許容している。上流の開発支援ツールという文脈に一致し、架空の属性や権限の違いを作っていない。P1からP2への結果と再現条件の受け渡し、情報不足時の再実行も自然につながる。

## Positions

AGREE: 二つの役割、四つのMust Have、既存の機能要件21 IDとNFR1〜NFR3を保つ方針に賛成する。利用者の目的が異なり、IDを付け替えただけの構成になっていない。

AGREE: 検査不能を全体結果として優先し、独立に確定した違反と未解決理由を両方残す方針に賛成する。P2が合格と誤認せず、修正と追加確認を判断するために必要である。

AGREE: US1.4を再実行と回帰検出のストーリーとして維持する。共通契約・判定と抽出の技術的な依存を明示し、独立試験と最終結合を区別する現方針は妥当である。D2・D3は明確化の提案である。

OBJECT: D1。AC1.4.6には、FR6.2で求める期待結果・終了状態の文書記載と、実使用ツール版の記録を明記する必要がある。上記文案で解消でき、新しい業務判断や範囲の再確認は不要である。

未解決事項はD1の草案への反映である。その他に、役割・目的・便益・結果の読み分けに関する異論はない。
