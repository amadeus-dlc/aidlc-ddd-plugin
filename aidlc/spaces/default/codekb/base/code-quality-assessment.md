全体テスト、配布物検査、インストーラ、Biome、rustfmt、Clippyは今回再実行していない。`test:coverage`は規則とケースの対応表の検証で、行・意味の網羅率ではない。読んだ設定には行カバレッジの閾値がない。

## Stored Spike Evidence

保存済みのsyn試作検証は31入力、実センサー比較4入力、不正リクエスト6入力である。今回、入力・スクリプト・保存済み結果は確認したが、`experiment:rust-syn`自体は再実行していない。

公開タプル2入力の見落としが、現行系の既知差として期待値に含まれる。したがって比較試験の成功は、現行センサーが全入力を正しく検査する証明ではない。過去のdarwin-arm64結果から他OS配布や全規則の互換性を推定しない。

## Required Verification for the Planned Slice

- 指定型ごとの正常・違反・検査不能を両言語で確認し、根拠から同じ規則を追えること。
- 型が不在、同名で曖昧、情報が不完全、空結果である場合を区別し、必要な情報がないときは正常にしないこと。
- 未知版、不正応答、結果欠落、ソース・設定の識別不一致を拒否できること。
- TypeScriptではclassの`#`、コンパニオンのクロージャという合意された正常形を扱い、公開readonly状態や`private`だけの宣言、計算名・spread・継承・型アサーションなどを黙って安全としないこと。一般形をすべて解析する要求ではなく、対応外を明示する境界を設けること。
- 一つの再実行コマンドで正常・違反・検査不能の期待結果を確認でき、期待値の不一致や検証自体の実行失敗を成功として終了しないこと。検査コマンドとテストランナーの終了条件を区別し、既存Rustの回帰検証も維持すること。

上記は次段階で具体化する設計・受入上の課題であり、実装済みの機能一覧ではない。

## Maintainability and Documentation

入力処理とRust Visitor、センサー入口と実行・規則の分離は追跡しやすい。所見の決定的なIDと整列は再現性に役立つ。一方、Rust構文抽出器759行・Rust規則437行へ処理が集まり、共通化時の結合点となる。今回の一規則のために全面分割することは提案しない。

Biomeのrecommended検査と整形設定がある。fixturesとvendored解析器は除外される。ルートのCI設定は未調査であり、CI全体が成功しているとは評価しない。既存の試作・共通契約資料は英日で用意されているが、今回英日全行比較は行っていない。
